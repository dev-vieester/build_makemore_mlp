# Contributing

Thanks for your interest in improving this learning project.

## Before making a change

- Open an issue or discussion first for larger changes so the scope can be agreed on.
- Keep changes focused and explain the learning or usability improvement they provide.
- Do not commit downloaded datasets, trained model checkpoints, or local environment files.

## Notebooks

- Keep the notebook runnable from top to bottom in a fresh environment using `requirements.txt`.
- Explain non-obvious model or training choices with concise Markdown cells.
- When changing training or data preparation, check that evaluation and sample-generation cells still run.
- Avoid committing transient output or excessively large notebook artifacts.

## Submitting changes

1. Create a focused branch.
2. Run the affected notebook cells or other checks relevant to your change.
3. Open a pull request describing what changed and how you checked it.
